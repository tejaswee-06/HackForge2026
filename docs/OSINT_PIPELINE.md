# OSINT pipeline

Ownership (work-division PDF): **Person 1** owns source connectivity and ingestion
(`backend/app/services/osint_ingest/`), **Person 2** owns OSINT analysis (`backend/astra_intel/osint.py`,
`correlation.py`, `engine.py`), **Person 3** presents findings (Sources page, Evidence inspector,
Graph inspector, Casebook).

## 1. Sources and collection (Person 1)
| Source | Adapter | Mode | Status |
|---|---|---|---|
| Labelled synthetic documents for the demo scenario | `load_fixture_documents` (`data/osint/<scenario>.json`, generated by `scripts/generate_osint_fixture.py`) | synthetic | implemented, tested |
| Simulation documents | `astra_intel.simulation` → `build_document` | synthetic | implemented, tested |
| GitHub REST issue/PR search | `GitHubIssuesSource.search` (exact quoted term, ≤30 items) | real | implemented; **tested with mocked HTTP only** (enable with `ASTRA_OSINT_GITHUB_ENABLED=1`) |
| Analyst-supplied public text | `POST /osint/documents` → `analyst_document` | inherits investigation mode | implemented, tested |

Every `SourceDocument` keeps: `doc_id` (hash of source/url/content), `source_id/name/type`,
`publisher_group`, `url` (http/https only), `title`, `published_at` (or null = unknown), `retrieved_at`,
`text` (≤200k chars), `content_hash` (sha256), `extraction_method`, `reliability` (rubric, not
probability) + `reliability_rationale`, `data_mode`, `collection_status` (collected/failed/partial),
`error`, `terms_note`. Failed collections are stored as failed records (never replaced by invented
content) and surface as "source unavailable" boundaries and in the source registry.
GitHub adapter: timeout, ≤2 bounded retries with backoff, 403/429 rate-limit detection
(`X-RateLimit-Remaining`, `Retry-After`, `X-RateLimit-Reset`; waits >30 s are reported, not slept),
shape validation, optional server-side `GITHUB_TOKEN` (never logged/returned). No scraping of HTML pages,
no login-walled content.

## 2. Extraction and validation (Person 2, `extract_indicators`)
* Types: `evm_address`, `tx_hash` (64 hex), `truncated_evm_address` (`0xabcd…123` / `...`),
  `bitcoin_address_candidate` (pattern only; unsupported chain).
* Longest-match-first span allocation (a tx hash is never also an address).
* EIP-55 checksum via pure-Python Keccak-256 (`keccak.py`, verified on official vectors):
  `checksum_valid`, `checksum_invalid`, `format_valid_no_checksum`.
* Each indicator: id, raw/normalized value, character span, ±120-char excerpt, sentence, validation,
  **stance** of the sentence (`incident_association`, `service_label`, `privacy_boundary`, `mixed`,
  `neutral`) from a documented vocabulary with simple negation handling, source/doc provenance,
  extraction method `regex_indicator_extraction_v2+sentence_stance_v1`.
* Source text is untrusted data: never executed, never given tool authority; rendered escaped.

## 3. Matching and correlation (`correlation.correlate`)
| match_type | quality | rule | evidence_kind |
|---|---|---|---|
| exact | 1.00 | full address equals a graph node (valid or absent checksum) | direct |
| strong | 0.75 | full address equals a node after lower-casing but checksum invalid | direct |
| strong | 0.60 | tx hash equals an observed transaction → both endpoints | indirect |
| weak | 0.40 | shortened form matches exactly one node | indirect |
| ambiguous | 0.00 | shortened form matches several nodes → attached to none | indirect |
| no_match | 0.00 | not in this investigation | none |

Each finding records: on-chain record (`matched_nodes`, `matched_event_ids`), OSINT record (doc,
indicator, excerpt, URL), `link_reason`, `features`, direct/indirect, freshness, contradictions,
`unknowns` (e.g. "control/ownership not established", "source predates the incident", "publication
time unknown", "ambiguous"). **A matching address is never treated as proof of control.**

## 4. Provenance, time and uncertainty
* Three clocks are kept separate: transaction (event) time, publication time, retrieval (observation)
  time. `predates_incident` = published before the case's first origin outflow → incident claims become
  *context* (prior activity), not support.
* Freshness = 0.5^(age/half-life) relative to the analysis reference time (cutoff, or the latest
  available record); `stale` after `stale_after_days`; unknown publication → `status: unknown`,
  `score: null` (missing, never "stale" and never negative).
* Replay availability: `observation` policy (default) = retrieval time; `publication` = publication time
  (fallback retrieval). Documents not yet available are excluded *before* extraction.

## 5. Contradictions and independence
* Contradiction: incident-association vs service-label (or a `mixed` sentence) on the same node from
  different documents → both findings `contradictory`, evidence status **Disputed**, claim status
  **Disputed**, lead status `disputed`, `evidence.contradiction_strength` penalty.
* Independence: Union-Find over documents sharing a content hash or publisher. Only the strongest
  finding per (group, stance) counts as hypothesis evidence; duplicates become context and
  `osint.independent_corrob` counts groups, not documents (tested with the synthetic mirror article).

## 6. From findings to the investigation
Per lead: `osint.indicator_match`, `source_quality`, `independent_corrob`, `source_freshness`
(supporting findings only), `evidence.contradiction_strength`. Evidence items `EV-OSINT-…` carry the
finding/doc/indicator ids, source URL, excerpt, match type, freshness and data mode; claims
`CLM-<lead>-OSINT` link them bidirectionally. Origin findings are case-level evidence shared by all
leads' hypotheses. The UI shows them in the Sources page (documents, indicators, match counts,
reliability, publication/retrieval time, failed collections), Evidence inspector (status chips,
excerpt, source link — synthetic `.invalid` links are announced instead of opened) and casebook.
