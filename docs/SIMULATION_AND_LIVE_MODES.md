# Simulation and live modes

## Modes and labels
| Mode | How it is selected | Records | Label shown everywhere |
|---|---|---|---|
| Demo scenario | default case `inv-ghost_attacks_synthetic_v1` / Settings → Demo scenario | Person 1 hand-authored fixture + `data/osint/…` documents | `SYNTHETIC / SIMULATED` |
| Simulation | `POST /api/simulations` / Settings → Simulation | generated by `astra_intel.simulation` (seeded) | `SYNTHETIC / SIMULATED` |
| Live wallet | `POST /api/investigations {chain_id, address}` / Settings → Live wallet | Etherscan V2 (server-side key) | `LIVE` (`real`) |
| Cached live | same query within `ASTRA_CACHE_TTL_SECONDS` | provider cache, original retrieval time kept | `CACHED` |
| UI fixture | `VITE_ASTRA_DATA_SOURCE=fixtures` or backend unreachable | original Person 3 fixtures | `UI FIXTURE` + banner |

Rules enforced in code and tests:
* No silent fallback: a live wallet query without a key returns `503 PROVIDER_NOT_CONFIGURED`
  (`degraded_mode: true`); the UI shows the error and keeps the current case.
* Live OSINT collection is refused (`409 MODE_CONFLICT`) on synthetic investigations, so synthetic and
  live evidence are never mixed. Analyst documents inherit the investigation's mode.
* If the backend is unreachable the UI shows a "backend unreachable — showing UI FIXTURE data" banner,
  a red/amber status and `UI FIXTURE` in the footer; fixture values are never presented as analysis.
* Reports and exports carry `data_label`, `synthetic`, notice text and source data modes.

## Simulation (real pipeline, not static mock data)
`astra_intel.simulation.generate(config)` produces **raw provider-shaped rows** (Etherscan field names)
and raw documents. `POST /api/simulations` then runs Person 1's `normalize_batch` (validation, dedupe,
failed-tx handling) and stores a normal investigation; every view, sensitivity run, replay and report
uses the same engine as live data. Nothing is precomputed: no scores, ranks, hypotheses or report text
are generated by the simulator. Ground-truth labels are returned only to the evaluation harness
(tested: they never appear in analysis output).

### Configuration (`SimulationCreate`, all validated/bounded)
| Field | Default | Meaning |
|---|---|---|
| `seed` | 42 | RNG seed; same config ⇒ identical records, investigation id and results (tested) |
| `scenario_kind` | incident | `incident` (exploit splitting tree + rapid forwarding + exchange deposit + router confounder), `benign` (exchange-like payouts over hours, two independent service labels), `insufficient` (few slow transfers, no discriminating sources) |
| `depth`, `branching` | 4, 3 | incident tree shape (capped at 400 tree nodes) |
| `noise_addresses`, `noise_transfers` | 12, 20 | unrelated activity (disconnected from the incident) |
| `disconnected_components` | 2 | isolated address pairs |
| `include_cycle`, `include_self_loop` | true | directed cycle back up the tree; self-transfer |
| `duplicate_records`, `failed_transactions` | 2, 1 | duplicate raw rows (dropped by ingestion), failed txs (excluded) |
| `repeated_edges`, `include_token_leg` | 2, true | repeated transfers on the same pair; ERC-20 leg (6 decimals) |
| `base_amount_eth`, `start_time`, `window_hours` | 420, 2026-10-01T02:14Z, 6 | amounts and time window |
| `osint_incident_report`, `osint_service_label`, `osint_contradiction`, `osint_stale`, `osint_missing_timestamp`, `osint_ambiguous`, `osint_duplicate`, `osint_outage` | true | document edge cases (exact/strong/weak/ambiguous matches, contradictory labels, stale & undated sources, a mirrored copy, a failed feed) |

All addresses/hashes are SHA-256-derived placeholders; URLs use the reserved `.invalid` TLD.
Possible outcomes are computed, not scripted: across 30 seeds per kind the engine leads with H1 for
`incident`, H2 for `benign`, H3 for `insufficient` (test `test_scenario_kinds_produce_outcomes_through_computation`
uses seed 9; the 60-scenario evaluation is in EVALUATION_AND_BENCHMARKS.md). Turning off public sources
moves an incident case towards H3 (tested).

## Live mode
* **Blockchain**: `ETHERSCAN_API_KEY` (server-side), Etherscan V2 `txlist` + `tokentx` for one address,
  `max_transfers ≤ 500`, timeout `ASTRA_PROVIDER_TIMEOUT_S`, `ASTRA_PROVIDER_MAX_RETRIES` with exponential
  backoff, 429/rate-limit handling, TTL cache labelled `cached`. One-hop neighbourhood only (documented).
  Optional time filter is applied after the bounded fetch and says so in `limitations`.
* **OSINT**: `ASTRA_OSINT_GITHUB_ENABLED=1` (+ optional `GITHUB_TOKEN`) → Sources page button
  "Collect public sources" → `POST /osint/collect` for the origin and top leads.
* **Verification status**: both live adapters are tested against mocked HTTP (success, timeout,
  rate limit, malformed, auth). They were **not exercised against the real services** in this package
  (no credentials) — see REMAINING_WORK.md.
